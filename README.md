<h1 align="center">Academic Repro</h1>

<p align="center"><strong>从论文图表与计算结果，回到可信、可运行、可检验的研究过程</strong></p>
<p align="center">简体中文 · <a href="README.en.md">English</a> · <a href="academic-repro/SKILL.md">Skill 规范</a></p>

Academic Repro 是面向 Codex 的学术图表与研究结果复现 Skill。它复现图表背后的仿真、训练、测量、统计或算法过程，并判断结果能否继续支撑同一局部论点。默认目标是局部论点等价，不是假定论文省略的细节都能恢复，也不是把一次成功运行写成对整篇论文的证明；只有用户明确要求且材料足够时，才追求精确数值或视觉一致。

## 安装与调用

```text
使用 $skill-installer 安装 https://github.com/SciToolsmith/academic-repro/tree/main/academic-repro
```

```text
使用 $academic-repro 复现这篇论文的图 1、图 6 和表 2；结果应能替换原图表而不改变相邻正文的论点。
```

以上两段是输入到 Codex 对话中的指令，不是终端 Shell 命令。

可提供论文与目标图表、论文与图表编号，或仅提供目标图片。仅有图片时，Skill 只重建像素中可以可靠识别的内容，不会把重绘称为原始实验复现。

## 核心判断

Academic Repro 先判断目标**如何产生、在论文中充当什么证据**，而不是只看外形：

- 仿真、训练、搜索、优化或统计产生的图、定量表、模型结构和拓扑，属于计算结果；即使看起来像结构示意图，也应复现其生成过程。
- 参数表和场景表通常是复现输入；定性文献比较、符号表和能力清单属于说明内容。
- 只有作者为解释理论、流程或机制而绘制、且本身不是计算输出的示意图，才交由科研示意图工具重建。
- 一张表可以同时含有输入列、计算结果列和说明列，应按列或单元分别判断。

复现作者工作流时，先把目标逐项绑定到入口、输入、关键参数和输出；目标相关作者源码与本机兼容环境可用时，默认保留原语言和原生运行时，例如实际运行 `.m` 就交付 `.m`，不为了熟悉或打包方便而改写成另一种语言。跨语言实现只在用户要求可移植或独立验证、它构成更强的科学检验，或原生路线确实受阻时作为主路线，并明确改变后的证据边界。方法来源和输入身份分开判断：作者源码使用重建输入，不等于精确重算论文目标。

论文图片可以帮助推断配色、字体、间距和线型等纯外观设置；坐标尺度、归一化、分箱、平滑等会影响解释的编码设置必须说明依据并单独核对底层数值。输入选择、预处理、模型参数、数据划分、种子、阈值和运行结果不能为了接近论文图片或报告数值而事后挑选。被用于校准的可见特征不能再充当独立验证。

## 什么算通过

复现结果通过所有适用的科学门槛才算通过：

1. **可信生成**：来自透明、可运行的数据、方程、模型或算法链，而不是用论点定义参数反向追数值。
2. **方法有效**：数据处理、目标量、比较方式、实验单位、不确定性和适用条件满足该研究类型真正需要的有效性要求。
3. **论点保持**：冻结的标准得到结果支持，且结论不超出当前证据路线能够证明的局部范围。

只有用户要求替换原图或忠实重建时，才额外检查**视觉语义保持**：保留承载比较关系的图表形式、子图关系、坐标、单位、图例映射、分组和归一化；不要求配色、字体、间距或逐像素一致。

阈值只有在来自论文、用户要求、方法有效性条件或可靠领域依据时才是硬门槛。任意设定的相似度或“收益保持率”可以用于诊断，不能单独把科学上可替换的结果判为失败。

论文报告值是待检验的参照，不是优化目标。若论文报告某指标超过 98%，而可比复现得到较低结果，Skill 先核对目标、输入或划分、预处理、指标定义、代码版本和随机协议，只做能够区分具体原因或改变证据状态的最小检查；随后分别判断绝对数值、相对提升或排序、定性趋势和机制。它不会无限追分，也不会仅凭不一致断言数据造假。即使精确发布的代码、数据、划分和指标反复未达到重要数值，结论也应是“发布材料在已测试条件下未复现该定量论点”，而不是未经证据支持的学术不端指控。

同一实验产生多个目标时，共享数据划分、基础场景、模型检查点和指标定义等固定条件，同时保留渗透率、拓扑、噪声或方法等有意变化。共享上游失败会影响依赖目标，某一目标自身失败不会掩盖其他目标的结果。

## 交付

默认只交付客户真正需要的内容：最终图或表、实际生成它的原语言源码、不可再生的必需输入、最小依赖与必要许可，以及短 README。README 开头用一段“复现声明”直接给出证据层级、论文目标或报告值、实测结果、局部论点中得到支持和未得到支持的部分、材料替代及限制，再给出一条准确命令。可再生成的 CSV/JSON、搜索记录、调试日志、过程草稿、验证清单、证据记录和复跑收据默认留在内部，除非用户要求审计包或这些数据本身有独立用途。

单目标交付保持扁平。多个可独立理解的复现目标按“复现单元”分文件夹，每个单元包含自己的结果和简短说明；可执行单元还包含实际入口代码与准确命令，根 README 只做索引。至少被两个单元实际使用的函数、数据或环境声明才放入 `common/`，只保留一份。无法分开的联动子图仍作为一个单元；总运行脚本可以存在，但不能成为唯一实现路径。若某一单元因原始数据缺失而受阻，它的文件夹只放一屏状态说明，不影响其他单元独立交付。

如果精确目标依赖未公开、不可再生的作者专有原始数据、私有切分、检查点或样本，Skill 只做一次有界权威核查；仍无兼容输入时，立即标记精确路线受阻，不继续广泛寻找替代物，也不自动写脚手架或做干净复跑。只读评估在对话中说明；用户要求复现文件或客户文件夹时，只交付一份一屏 README，写清目标、缺失项、核查范围和最小解阻材料。替代数据复现、像素近似或未来脚手架只有用户另行选择时才做。论文定义的仿真、公开基准输入和不影响科学结果的外观细节不触发这一闸门。

证据强度按风险分级：只读评估不创建记录；普通单目标复现保留一份紧凑摘要；只有机器可核验正式包或明确声称“已验证可复跑”时，才绑定证据记录并做干净复跑；随机性、数据划分、泄漏、重复试验等检查只在可能改变结论时启用。这样不会为了填满通用模板而浪费时间和 token。

Skill 的科学判断不依赖特定操作系统。仓库内的辅助脚本需要 Python 3.10+，当前面向 Linux/macOS；完整 Windows 流程暂不支持。PDF 自动定位另需 `Pillow`、`pdfplumber` 和 Poppler，目前自动识别英文 `Fig.`/`Figure` 加正整数；中文图号、补充图、表格、子图或其他复杂标签可由用户提供目标文件或使用经审核的人工标签绑定。完整规则见 [Skill 规范](academic-repro/SKILL.md)。

```bash
git clone https://github.com/SciToolsmith/academic-repro.git
cd academic-repro
python -m pip install -r academic-repro/requirements.txt
python -m unittest discover -s tests -v
```
